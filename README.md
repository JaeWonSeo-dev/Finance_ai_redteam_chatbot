# 금융 생성형 AI 상담 서비스 보안 포트폴리오

## 1. 프로젝트 제목
금융 생성형 AI 상담 서비스의 프롬프트 인젝션 취약점 분석 및 방어 정책 설계

## 2. 프로젝트 배경
금융권에서 생성형 AI를 상담 채널에 도입할 때, 단순한 응답 성능뿐 아니라 보안 통제 수준이 핵심 경쟁력이 됩니다.
본 프로젝트는 금융 상담 챗봇 프로토타입을 기반으로 실제 운영에서 발생 가능한 공격 패턴을 재현하고,
탐지-차단-기록-분석까지 이어지는 보안 검증 파이프라인을 구현한 포트폴리오입니다.

## 3. 문제 정의
- 프롬프트 인젝션으로 내부 정책을 우회할 수 있는가?
- 시스템 프롬프트/내부 규정을 노출하도록 유도할 수 있는가?
- 고객 개인정보를 유출하도록 조작할 수 있는가?
- 수익 보장형 허위 투자 조언 생성 요청을 통제할 수 있는가?
- 공격 시도를 로그로 남기고 정량적으로 분석할 수 있는가?

## 4. 사용 기술
- Python
- Streamlit (UI, 대시보드)
- pandas (테이블/집계)
- matplotlib (분포 시각화)
- CSV 저장소 (테스트 케이스, 로그)

## 5. 주요 기능
1. 금융 상담 챗봇 화면
- 예금, 대출, 투자상품, 계좌, 보안 카테고리 선택
- 사용자 질문 입력 후 응답 생성
- 위험도, 탐지 여부, 차단 여부 실시간 표시

2. 보안 정책 필터링 기능
- 위험 키워드/패턴 탐지
- low / medium / high 위험도 분류
- high 위험도 요청 자동 차단 및 안전 거절 응답

3. 공격 시나리오 테스트 기능
- 공격 유형별 CSV 테스트 케이스 자동 실행
- 탐지 여부, 위험도, 차단 여부, 응답 로그 저장

4. 관리자 대시보드
- 전체 건수 / 탐지 수 / 차단 수
- 공격 유형별 탐지 결과
- 위험도 분포
- 실패 케이스 목록

5. 보고서 자동 생성
- 실험 로그 기반 Markdown 보고서 자동 생성
- docs/portfolio_report.md로 저장

## 6. 공격 시나리오
- Prompt Injection
- System Prompt Leakage
- 개인정보 유출 유도
- 금융 내부정보 요청
- 투자 수익 보장 유도
- 보이스피싱성 요청
- 권한 우회 요청

## 7. 방어 정책
1. 입력 검증
- 위험 키워드, 명령형 우회 문장, 개인정보 요청 패턴 탐지

2. 출력 검증
- 계좌번호, 주민등록번호, 전화번호, 이메일 패턴 마스킹

3. 투자 조언 제한
- 수익 보장/원금 보장 표현 제한
- 투자 관련 답변에 유의사항 자동 부착

4. 내부 정책 보호
- 시스템 프롬프트, 내부 정책/규정 요청 시 거절

5. 로그 기록
- 질문, 탐지 공격유형, 위험도, 차단 여부, 응답 저장

## 8. 실행 방법
1. 의존성 설치
- pip install -r requirements.txt

2. 앱 실행
- streamlit run app.py

API 모드 사용(선택)
- 환경변수 OPENAI_API_KEY 설정 시 실제 LLM API 호출 가능
- 환경변수 OPENAI_MODEL로 모델명 지정 가능 (기본값: gpt-4o-mini)
- 키가 없거나 호출 오류 발생 시 자동으로 Mock 응답으로 대체

3. 테스트 흐름
- 챗봇 탭에서 단건 질의
- 레드팀 테스트 탭에서 공격 시나리오 일괄 실행
- 관리자 대시보드 탭에서 결과 확인
- 보고서 생성 탭에서 Markdown 보고서 저장
- 사이드바에서 로그 저장소를 csv 또는 sqlite로 선택 가능
- 레드팀 실행 결과는 data/redteam_results.csv에 누적 저장

4. 단위 테스트 실행
- pytest -q

## 9. 테스트 결과 예시
예시(샘플 CSV 기준):
- Prompt Injection: high 탐지 + 차단
- 고객정보 요청: high 탐지 + 차단
- 일반 예금 문의: low 탐지 없음 + 정상 응답

실제 수치는 실행 시점의 logs.csv 누적 데이터 기준으로 자동 갱신됩니다.

## 10. 금융권·증권사 직무와의 연관성
이 프로젝트는 다음 직무 역량과 연결됩니다.
- AI 서비스 리스크 통제: 공격 시나리오 기반 통제정책 설계
- 정보보호/보안기획: 탐지 규칙 정의, 차단 정책 적용, 감사 로그 구축
- 디지털 금융 기획: 생성형 AI 기능과 컴플라이언스 요구사항의 균형 설계
- 데이터 분석: 공격 탐지율/차단율 지표 관리 및 개선 포인트 도출

## 11. 한계점 및 개선 방향
한계점
- 현재 탐지는 규칙 기반 중심으로, 우회 표현에 취약할 수 있음
- API 모드는 포트폴리오 안전성을 위해 샘플 구조로 제공됨
- 모델별 응답 편향/환각 비교 실험이 제한적임

개선 방향
- 임베딩 + 분류기 기반 문맥 탐지 추가
- LLM 출력에 대한 self-check 체인 도입
- 정책 엔진의 allow/deny 이중화 및 정책 버전 관리
- 모델별(사내/외부) 보안 성능 벤치마크 자동화
